第八章 · 08 · CCF A/B 写作细讲

顶会论文写作教程

这章是教你怎么写，不是空讲「要有贡献、要有创新」。每一节都给你：写之前填什么、英文句式怎么套、差句/好句对照、写完自检。示例方法名用模板里的 DPCNet（Dual-Path Calibration Network）；你写自己的稿时，把任务、模块名、数字全部换成自己的。

目标：能对着本页，用 Cursor 按节写出可编译英文 LaTeX，并把表格里的真实实验数字填进去。

0. 写之前先填这张表（不填就开写，一定空）

打开记事本或 Markdown，把下面每一格写成具体名词，不要写「提升性能」「更好建模」。写摘要、引言、方法时，只允许用这张表里的词。

要填的项怎么填（示例用 DPCNet）
任务一句话视觉识别：输入 RGB 图，输出类别（如 CIFAR-100 / ImageNet 协议）
方法全称 + 缩写Dual-Path Calibration Network（DPCNet）——全文只用这一套
一个核心缺口现有管线常只强化局部或全局之一，缺少显式双路径校准
挑战 1（建模难点）局部证据选择不可靠：纹理噪声/伪相关被放大
挑战 2（与 1 独立）跨区域一致性弱：全局聚合混入冲突语义
模块 1 本名（对挑战1）Local Evidence Refinement（LER）——禁止写 Innovation A
模块 2 本名（对挑战2）Global Consistency Calibration（GCC）
数据集与划分数据集名、类别数、train/val、评估协议是否与 baseline 一致
主指标 + 次指标Top-1；约定 Top-5 / Params / FLOPs 是否计入「全面超」
Baseline 名字与代码 method=baseline 完全一致的那条结果
对照方法（建议 ≥8）ResNet、SE、CBAM、ViT、DeiT、Swin、ConvNeXt…（同协议复现）
你已跑通的数字贴表：方法 | 主指标 | 备注；没有数字就先别写 Experiments
消融变式名w/o LER、w/o GCC、w/o fusion——用模块本名

铁律：正文永远写模块本名。辅导流程里的 A/B 只在第七章对话用，不进论文、不进图表标题。

1. 全文结构与边界

七大块各管一块事。写错边界会出现「引言报点」「方法贴表」这类硬伤。

章节这一节要完成的事绝对不要写
Abstract独立可读的 150–250 词故事引用、公式、「见图 x」、夸张词
Introduction缺口 → 两挑战 → 方案对应 → 可证伪贡献公式、实验数字、模块内部细节
Related Work两子节评前人 + 收束引出本文完整讲自己的网络结构
Method符号、公式、算法、复杂度对比表、准确率、可视化结果
Experiments设置→主对比→消融→参数→可视化→错误新提未在方法里定义的模块
Conclusion总结 / 局限 / 未来（一一对应）新文献、新公式、新实验数字
References35+ 可核验真实文献虚构作者/年份/会议

推荐写作顺序（和阅读顺序不同）：先锁上表 → Method 骨架 → Introduction → Related Work → Experiments（有表再写）→ Abstract → Conclusion。

2. 摘要 Abstract（最后写，但先学会链）

是什么：审稿人最先读的 150–250 词完整故事。它是引言的凝练，但禁止整句复制引言。

六句叙事链（按这个顺序写英文）：

  1. 任务价值（领域里为什么还值得做）
  2. 核心缺口（一句话，和你表里「一个核心缺口」一致）
  3. 本文方法：首次写出全称 + 缩写
  4. 机制一句话（点两个模块在干什么，不展开公式）
  5. 实验优势概括（可写「优于强 CNN / Transformer / hybrid baselines」；具体数字可放正文表）
  6. 意义 / 适用范围收一句

可套句式（把括号换成你的词）：

[Task] remains challenging when [concrete failure mode]. Existing [CNN / Transformer / hybrid] pipelines often [single-route behavior], leaving a gap in [your core gap]. We present the [Full Name] ([ABBR]), which [module1] and [module2] under a unified objective. The design targets [challenge1] and [challenge2]. Experiments on [datasets] show consistent gains over [baseline families], supported by ablations and visualizations.
差（空）We propose a novel and powerful network that greatly improves performance and can be widely applied.
好（具体）We present DPCNet, which couples Local Evidence Refinement with Global Consistency Calibration to stabilize local cues and cross-region semantics under one training objective.

硬约束：无 \cite、无公式、无「见图 x」；禁用 groundbreaking / unprecedented / empower / significantly empower 等夸张词。

  • □ 首次出现写了全称+缩写，且与引言、方法一致
  • □ 能指着摘要说出「缺口是哪一句、两模块各对哪挑战」
  • □ 没有从引言复制整句

3. 引言 Introduction（四段论 + 贡献）

是什么：让审稿人相信「问题真、缺口准、方案对症」。纯段落，不列 bullet；批判要落到建模机制，不要只说「效果不好」。

3.1 第一段 · 任务背景（有引用，不给方案）

写：领域是什么 → 应用/科研价值 → 权威文献撑趋势 → 点到痛点（仍是背景层）。

[Domain] has become a foundational capability for [apps]~\cite{key1,key2}. With [trend], accuracy on [benchmarks] has improved, and backbones are routinely transferred to [downstream]~\cite{key3}. Despite this progress, systems still fail when [concrete failure: occlusion / clutter / domain shift]. These errors matter because [downstream consequence].
差Deep learning is developing rapidly and has been applied in many fields, which is of great significance.
好Deep visual recognition underpins retrieval and perception pipelines~\cite{deng2009imagenet,he2016resnet}, yet decisions remain brittle under occlusion and conflicting long-range context.

3.2 第二段 · 现有方法 → 收敛到同一个核心缺口

按「传统 → 改进 → 当代主流」递进。每一类：一句优点 + 一句机制缺陷。全部缺陷必须收敛到你表里的同一个核心缺口，不要列三个互不相关的槽点。

Classical CNNs provide strong local inductive biases~\cite{...}, yet their receptive-field growth is primarily hierarchical. Vision Transformers model long-range dependencies~\cite{...}, but global mixing can dilute locally decisive evidence. Hybrid designs narrow the gap~\cite{...}; nevertheless, many pipelines still optimize a single dominant route. The core modeling limitation is therefore [ONE gap sentence].

段末可接动机图（可选）：

The core modeling limitation of existing methods is illustrated in Figure~\ref{fig:motivation_example}.
差CNNs are not good enough. Transformers also have problems. There is still room for improvement.
好Many pipelines optimize either local operators or global attention alone; the missing piece is an explicit dual-path calibration mechanism under one objective.

3.3 第三段 · 两大挑战（必须相互独立）

从「一个缺口」拆出两个挑战。每个挑战写清：难点本质 → 建模瓶颈 → 现有方法为何不够。禁止把两挑战写成同一句话的两半（例如「既要准又要稳」）。

This limitation raises two coupled scientific challenges. First, [challenge1 name]: [mechanism] so that [bad consequence]~\cite{optional}. Second, [challenge2 name]: [mechanism] so that [bad consequence]~\cite{optional}. Existing single-route designs typically mitigate one challenge more than the other.
差Challenge 1 is improving accuracy. Challenge 2 is improving robustness.
好Challenge 1 is unreliable local evidence selection (spurious textures amplified). Challenge 2 is weak cross-region consistency (incompatible semantics mixed by global aggregation).

3.4 第四段 · 提出方法（模块 ↔ 挑战一一对应）

写出全称+缩写；简述构成；明确「模块1对挑战1、模块2对挑战2」。仍不写公式、不报准确率。

To address both challenges, we propose the [Full Name] (\textbf{[ABBR]}). [ABBR] maintains a [module1] path for Challenge~1 and a [module2] path for Challenge~2, then fuses the calibrated streams. The joint objective encourages complementary rather than redundant corrections.

3.5 贡献段（可证伪，不是口号）

连贯段落，可用 (i)(ii)(iii)。每条都能被后文实验证伪。不要写 “The main contributions are as follows:” 再接中文式项目符号列表。

Our contributions are threefold. (i)~We formulate failures around a single gap---[gap]---and derive two explicit challenges on [c1] and [c2]. (ii)~We instantiate [ABBR] with [module1] and [module2], consistent notation, and a complete training procedure. (iii)~We validate the design with comparisons, ablations, sensitivity, visualization, and error analysis under a fixed protocol.
  • □ 缺口只有「一个」，两挑战从它拆出且互不重复
  • □ 模块本名与挑战一一对应；无 Innovation A/B
  • □ 无公式、无 Top-1 数字

4. 相关工作 Related Work

是什么：定位你与前人的差异，不是文献清单。只评前人，不在这里完整介绍自己的网络。

结构：两个子标题，逻辑互不重叠。常用切法：

  • 任务线 / 技术线（例如「局部卷积与注意力」vs「Transformer 与混合全局建模」）
  • 或 CNN 路线 / Transformer 路线

每一篇代表作的固定写法（背下来）：

XXX et al.~\cite{key} propose [core idea] for [task setting]. Their design [task adaptation + underlying operator]. It is effective at [strength], yet [mechanism limitation — not “accuracy is low”].

代表作细评 2–4 篇；同类其余合并引用，例如 \cite{a,b,c}。禁止按年份流水账。

两节结束后的收束段（必须有）：

Across both lines, existing methods still [shared shortboard tied to your ONE gap]. This leaves a research blank in [gap restated]. In contrast, [ABBR] keeps an explicit [dual-path / your idea] rather than replacing one backbone family with another.
差Many methods have been proposed in recent years. Our method is different and better.
好CNNs remain strong at neighborhood structure but lack explicit consistency correction; Transformers excel at long-range mixing yet can over-smooth local cues. DPCNet targets joint calibration instead of swapping backbone families.
  • □ 两个子标题互不重叠
  • □ 代表作都有「优点 + 机制局限」
  • □ 收束段引出本文动机，但未展开公式

5. 方法 Method（可复现的符号化说明）

是什么：别人照着符号和算法能复现你的训练流程。缩写必须与摘要、引言完全一致。

5.1 Problem Formulation

先定义输入输出与符号，再给优化目标。符号首次出现立刻释义。

Let an input image be $\mathbf{X}\in\mathbb{R}^{H\times W\times C}$ with label $y\in\{1,\ldots,K\}$. A backbone $f_{\theta}$ maps $\mathbf{X}$ to $\mathbf{F}\in\mathbb{R}^{h\times w\times d}$: \begin{equation} \mathbf{F}=f_{\theta}(\mathbf{X}). \label{eq:backbone} \end{equation} Our goal is to learn ... minimizing \begin{equation} \min_{\theta,\phi,\psi}\;\mathbb{E}[\mathcal{L}_{\mathrm{cls}}(\cdot)+\lambda\mathcal{L}_{\mathrm{cal}}(\cdot)]. \label{eq:obj} \end{equation}

公式行文规矩：公式前有引导句；公式后用 “where …” 解释符号；每个关键式都有 \label{eq:...}；全文同一符号不换含义。

5.2 Model Overview

自上而下：数据流 → 创新模块 vs 标准组件 → 回扣两大挑战。段末可接架构图：

The overall architecture of the proposed framework is illustrated in Figure~\ref{fig:model_arch}.

图内模块名必须用本名（LER / GCC），禁止 Innovation A/B；图上不要写方法名大横幅（标题留给 caption）。

5.3 各模块（先机理，再公式）

每个创新模块至少：

  1. 一段话：解决哪个挑战、输入输出是什么
  2. ≥2 条带 label 的公式（中间量 → 输出）
  3. 符号即时解释；说明如何接到下一模块
Given $\mathbf{F}$, we compute a local importance map $\mathbf{A}_{\ell}$ and a refined field $\mathbf{F}_{\ell}$: \begin{equation} \mathbf{A}_{\ell}=\sigma\big(\mathrm{Conv}_{1\times1}(\mathbf{F})\big), \label{eq:local_attn} \end{equation} where $\sigma$ denotes a sigmoid. We then obtain \begin{equation} \mathbf{F}_{\ell}=\mathbf{A}_{\ell}\odot\mathbf{F}, \label{eq:local_refine} \end{equation} which addresses Challenge~1 by reweighting local responses before global calibration.

模板要求 Method 里 numbered 公式尽量 ≥10；不要用一条残差通式敷衍两个模块。

5.4 Training procedure

用 Algorithm 环境写清：输入、输出、前向、损失、更新、停止条件；\label{alg:train}。补充优化器、epoch、学习率调度等可复现设定（细节也可在实验设置重复）。

5.5 Complexity

分别写训练阶段与推理阶段的时间复杂度，以及空间复杂度；指出受哪些超参影响；相对 baseline 理论比较一句即可。

Method 节禁止出现 Top-1、对比表、「优于某某方法 xx%」。那些全部放到 Experiments。

  • □ 每个创新模块 ≥2 条带 label 公式
  • □ 有 Algorithm + Complexity
  • □ 无实验数字

6. 实验 Experiments（顶会结构，数字必须真实）

没有对照表就不要开始写这一节。所有数字来自你自己跑的日志；模板里的 [TOP1] 之类必须替换。

6.1 Setup 实验设置（按这个顺序写）

  1. 数据集：名称、规模、类别数、划分、为何用它（一句话）
  2. 对比方法：每个方法一句建模特点（不是只列名字）
  3. 评价指标：主指标、次指标、越高/越低越好
  4. 实现细节：优化器、学习率、batch、epoch、种子、硬件、数据增强
We evaluate on [dataset] with [split]. Competitors include [M1] ([one-line mechanism]), [M2] (...), ... We report [metric]. All methods are trained under the same protocol: [optimizer], [epochs], [seed], on [GPU].

6.2 Performance Comparison（主对比四段写法——照着填）

正文对应一张主表。下面四段每段建议：8–15 词标题句 + 60–80 词展开（页限紧可略缩，但结构不能丢）。

第 1 段 · 总述最优

[ABBR] achieves the best overall [metric] on [dataset]. It reaches [YOUR_NUM], outperforming the strongest baseline [NAME] ([BASE_NUM]) by [DELTA]. The gain is consistent with dual-path calibration: [one mechanism reason tied to challenges], rather than a larger backbone alone.

第 2 段 · 基线类别对比 1（例如强 CNN / 带注意力 CNN 优于轻量 CNN）

Among convolutional baselines, [StrongCNN] outperforms [LightCNN] ([a] vs [b]). This gap suggests that [mechanism: capacity / attention reweighting] matters when [dataset property]. However, even [StrongCNN] still trails [ABBR], indicating that local reweighting alone does not solve [challenge2].

第 3 段 · 基线类别对比 2（例如 Transformer / hybrid 与 CNN 家族）

Transformer-style models such as [ViT/Swin] improve long-range modeling over classical CNNs ([c] vs [d]), yet can underperform [ABBR] when local cues are decisive. This pattern aligns with Challenge~1: global mixing without local refinement may dilute discriminative evidence.

第 4 段 · 总体机制收束

Overall, [ABBR] improves over convolutional, attention-augmented, and transformer baselines under the same protocol. Quantitative gaps are largest against [weakest_family] and remain positive against [strongest_baseline]. These results support that addressing both [c1] and [c2] jointly is more effective than strengthening a single representation route.
差As shown in Table 1, our method is the best. It can be seen that the proposed method has obvious advantages.
好DPCNet reaches 82.1% Top-1, exceeding ConvNeXt-T (80.4%) by 1.7 points; the margin over SE-ResNet suggests local attention alone leaves cross-region conflicts unresolved.

上例数字是教学假想格式；你必须换成自己表里的真实数，没有就先空着别编。

6.3 Ablation 消融

先写清「做了什么、为了验证什么、每个变式去掉什么」，再分析数字。

We ablate [ABBR] by removing [LER] (w/o LER), removing [GCC] (w/o GCC), and removing the fusion term (w/o fusion). w/o LER drops to [n1], showing Challenge~1 is not covered by the global path alone. w/o GCC drops to [n2], showing Challenge~2 remains when only local refinement is kept. The full model recovers [n_full], indicating the two paths are complementary.

消融名用模块本名；不要写 w/o A、w/o Innovation B。

6.4 Parameter Analysis

选 1–2 个关键超参（如损失权重 λ、融合维度、窗口大小）。写法：参数含义 → 扫描范围 → 趋势 → 选用默认值的理由 → 与挑战的关系。

We vary $\lambda\in\{0.1,0.5,1.0,2.0\}$. Performance peaks at $\lambda=[best]$ and degrades when $\lambda$ is too small (under-regularized consistency) or too large (classification signal dominated). We therefore set $\lambda=[best]$ in all main experiments.

6.5 Visualization

自然段落，不要只丢图不解释：

  1. 为了验证什么（对应哪一挑战）
  2. 做了什么可视化、怎么做（Grad-CAM / t-SNE / 注意力图）
  3. 结果看到什么现象
  4. 结论与依据（同种子、同图对比等）
To examine whether LER focuses on decisive local evidence, we visualize Grad-CAM maps for baseline and [ABBR] on the same images and seed. [ABBR] concentrates on [object parts], whereas the baseline activates [background / spurious regions], supporting Challenge~1.

6.6 Case / Error Analysis

至少各举一类：成功案例（为什么成功，挂到模块）+ 失败模式（什么假设被打破、适用边界）。

Success cases often involve [clutter with clear local parts], where LER preserves cues while GCC suppresses conflicting regions. Failure cases remain under [extreme occlusion / tiny objects / severe domain shift], where both local evidence and global context are insufficient—an intrinsic limit of the current calibration assumption.
  • □ Setup 含数据/对照/指标/实现细节
  • □ 主对比按「最优 + 两类基线对比 + 机制收束」四段写
  • □ 消融用模块本名；有参数、可视化、错误分析
  • □ 所有数字来自自己的表，无编造

7. 结论 Conclusion（三块递进）

不要照搬摘要。三块各自成段；Future Work 必须和 Limitations 一一对应。

7.1 Summary

We presented [ABBR] for [task], motivated by a single gap in [gap]. The framework instantiates [module1] and [module2] to address [c1] and [c2]. Under a unified protocol, comparisons and ablations support that joint calibration improves over single-route baselines.

7.2 Limitations（写建模假设，不写「显卡不够」）

差Our method needs more GPUs and larger datasets. Time was limited.
好DPCNet assumes that local evidence and global consistency can be calibrated from the same supervised labels; under extreme occlusion where neither cue is reliable, the calibration objective provides limited additional signal.
First, [assumption1] may break when [condition]. Second, [assumption2] increases [cost/complexity] and may be redundant for [easy cases].

7.3 Future Work（逐条对应局限）

To address the first limitation, we plan to [concrete modeling fix: e.g., uncertainty-aware gating / multi-view consistency]. To address the second, we will study [lighter fusion / adaptive λ / task transfer to detection].

禁止空泛愿景：「探索更多场景」「结合大模型赋能」——除非你能写出具体机制改动。

  • □ Summary 回扣开篇挑战，形成闭环
  • □ 局限在机制/假设层
  • □ 未来工作与局限条数对应、可落地
  • □ 无新文献、新公式、新实验数字

8. 空话与禁用写法（改稿时对照删）

空话 / 禁用问题改成什么
novel / powerful / significantly improve（无数字）无法证伪写出相对谁、指标、差值
as we all know / in recent years… rapidly套话开场直接写任务 + 文献
existing methods have limitations没说机制指出缺哪类算子/假设
Innovation A / Module B辅导代号进正文模块本名 LER / GCC
groundbreaking / unprecedented / empower夸张删掉，改事实陈述
It can be seen that / Obviously翻译腔直接给判断 + 数字
引言里报 Top-1越界数字只放 Experiments
方法节贴对比表越界表只放 Experiments
结论写「数据太少」当唯一局限推脱写建模假设边界
编造未读过的引用学术不端风险Scholar 核到再 cite

9. 参考文献

  • 全部进 refs.bib，正文只用 \cite{key}
  • 目标 35+；优先近年顶会/期刊；每条用完整标题在 Scholar 核能到
  • 禁止虚构作者、年份、会议；预印本与正式发表勿重复混用
  • 教程自带 writing/refs.bib 学格式；正式投稿再核 DOI/页码
  • Cursor 若补文献：只让它列「标题 + 检索词」，你核实后再写入 bib，禁止让它直接捏造条目

10. 用 Cursor 按节写作（可直接复制）

总规则：一次只生成一节；用 @ 挂上创新点文档、数字表、refs.bib；生成后你必须人工核对术语与数字。

10.1 锁术语（先发这一条）

请阅读 @docs/innovation.md（或我贴的创新点说明）。
先不要写正文。只输出一张术语表确认：
- 方法全称与缩写
- 一个核心缺口（一句话）
- 挑战1 / 挑战2（机制级，不要“提高精度”）
- 模块1本名↔挑战1，模块2本名↔挑战2
- 禁止使用 Innovation A/B 字样
我确认后，再按节写 LaTeX。

10.2 引言

按深基课规范，只生成 Introduction 英文 LaTeX（四段论+贡献段）。
方法缩写：____
核心缺口：____
挑战1：____  挑战2：____
模块对应：____ ↔ 挑战1；____ ↔ 挑战2
背景与现有方法必须使用 @writing/refs.bib 已有真实 key，禁止编造文献。
不要写公式和实验数字。批判写到建模机制。

10.3 相关工作

只写 Related Work：两个子节标题 + 正文 + 收束段。
风格：XXX et al.~\cite{key}；代表作细评，其余合并引用。
从 @writing/refs.bib 选用真实条目；若不够，只列出需补充的真实论文标题供我核实，不要虚构 BibTeX。
不要展开本文公式。

10.4 方法

写 Method 英文 LaTeX：
Problem Formulation / Model Overview / 各模块公式（每式 \label）/
Algorithm 训练表（\label{alg:train}）/ Complexity。
缩写与符号与引言一致；每个创新模块≥2条公式；numbered 公式尽量≥10。
禁止出现实验指标与对比表。

10.5 实验（必须贴你的表）

按顶会结构写 Experiments。数字只能使用我提供的表格，禁止改数或编造：
（在此粘贴：主对比表 / 消融表 / 参数扫描）
小节顺序：Setup → Performance Comparison → Ablation → Parameter → Visualization → Error。
Performance Comparison 必须按四段：最优总述 / 基线类别对比1 / 基线类别对比2 / 机制收束。
消融变式名称用模块本名，不要 Innovation A/B。

10.6 摘要与结论（最后）

根据已写好的 Introduction 与 Experiments，重写 Abstract（150–250词，无引用无公式）
以及 Conclusion（Summary / Limitations / Future Work；未来工作与局限一一对应）。
不要照搬引言原句；不要新文献与新实验。

生成后你要做的三件事：① 全文搜索 Innovation / Module A 删掉；② 抽查 5 条 \cite 是否真在 bib；③ 表中每个数字对一下训练日志。

11. 推荐写作日程（按天拆，避免空想）

  1. 第 0 天：填完「写之前那张表」；主对比与消融表定稿（数字冻结）
  2. 第 1 天：Method 公式与 Algorithm（可先不管文采）
  3. 第 2 天：Introduction 四段论 + 贡献；Related Work 两子节
  4. 第 3 天：Experiments 全文（严格按表）；补可视化段落
  5. 第 4 天：Abstract + Conclusion；通读边界与空话表；编译过 bib

页限不够时优先砍：Related Work 合并引用、Parameter 缩成一段、可视化减一张——不要砍挑战↔模块对应和消融。
